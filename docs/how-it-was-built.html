How GenNAI was built with AI

AI agents planned, wrote and checked the code under written rules. I set the goals, the constraints and every decision. Each claim on this page comes from the repo, its history or a saved run.

The loop every change went through

The lead model never accepted "done" from a worker. Green steps are the checks.

1 · SpecRules first

Finish, don't expand. Demo first. Measure every claim.

2 · PlanOpus

Splits the work, decides the design, writes self-contained briefs.

3 · BuildSonnet subagents

One brief each: goal, owned files, constraints, proof command.

4 · ProveRun the proof

Opus reads the diff and runs the command itself.

5 · Live runReal pages

Demo, automationexercise.com, the-internet.herokuapp.com.

6 · CILint + tests

On GitHub, per pull request; merged only when green.

Timeline

  1. Dec 2025 · Course versionSpecs in prompts/, most code generated. Best efficiency score and highest mark, but about 11,700 lines whose phases no longer connected. Human review was random.random().
  2. Nov 2026 · The specWritten in a separate planning chat: the Ponytail rules, demo first, a verified free model, LLM safety as requirements, read-only references, git rules and model roles.
  3. Finish the core · PR #1One-command pipeline on three sites. Live runs exposed bugs: an off-screen skip link, 503 pages misread as missing locators, a 5 s page-load timeout. Each was fixed and re-run. Gemini measured live: one call per run, gate accepted all specs. 36 tests.
  4. Showcase · PR #3Tabbed report with filters, LLM response time and tokens, Phase 3 self-check, a fix for .env comments read as keys. 40 tests.
  5. Course features · PR #2A parallel session on its own branch: crawl, human review, run history and flaky tests, login, notifications, web UI. One commit per feature, no subagents. 88 tests.

How claims were checked

Run it for real

Every feature on the demo and public practice sites. Report and web UI clicked through in a real browser.

Adversarial tests

Prompt-escaping labels, hostile strings through codegen, invented elements, a code field from the model, <script> in the report.

Measured numbers

Provider-reported tokens, timed responses, README tables from saved runs in examples/.

Docs checked against code

When a draft named three regression tests that didn't exist, the doc was corrected, not the claim kept.
