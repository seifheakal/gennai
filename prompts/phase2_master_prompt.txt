**Test Generation Algorithms**:

EQUIVALENCE PARTITIONING (EP)
- Partition input domain into equivalence classes
- For text input: Valid | Invalid | Boundary
- For button: Clickable/Enabled | Disabled/Blocked
- For dropdown: Valid Option | Invalid Option | Empty State
- Test one representative from each class

BOUNDARY VALUE ANALYSIS (BVA)
- Test at boundaries of input domain
- For length: 0, 1, max-1, max, max+1
- For numbers: min, min+1, max-1, max
- For dates: min_date, today, max_date

STATE COMBINATION TESTING
- Test how elements interact with each other
- Use Phase 1's state graph to identify sequences
- Workflow tests: login → search → filter → sort → export

## KEY DETAILS EXPLAINED

**Why This Matters**

Phase 1 discovered the elements. Phase 2 generates intelligent test cases.
Phase 3 will generate test code. Phase 4 will execute the tests.

If Phase 2 fails: Phase 3 gets garbage input → generates garbage code 
→ Phase 4 has nothing to execute.

If Phase 2 succeeds: Phase 3 gets high-quality test specifications → generates 
reliable test code → Phase 4 produces trust metrics.

**Why HITL 2.0 Is Different**

This isn't "AI generates tests in isolation."

This is "AI generates + humans guide + system learns + improve together"

Flow:
1. Generate test case
2. Show to human with explanation
3. Get feedback: Approve | Reject | Modify
4. Record feedback
5. Extract patterns from feedback
6. Adjust future test generation
7. Next test is better because we learned

**Why 85% Coverage Matters**

100% coverage is impossible (infinite test scenarios).
0% coverage is useless (no tests).
85% is **smart** - covers 85% of elements intelligently.

How:
- High confidence elements: 2-3 tests each
- Medium confidence: 4-5 tests each
- Low confidence: More tests or skip (document gap)
- Prioritize by risk level
- Prioritize by coverage gap
